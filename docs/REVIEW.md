## フォーム導入の準備と条件

現時点では入力欄や送信ボタンを置きません。導入時は、利用目的・項目・送信先・保存期間・委託先・費用・国外移転等を先に確認し、承認された個人情報方針を掲載します。サービスのアカウント作成や課金は未実施です。

GitHub Pages自体にサーバーの送信処理はありません。送信方式を承認後に選び、秘密情報をブラウザーへ埋め込まず、送信先での検証・レート制限・迷惑送信対策・エラー処理・同意表示を検証してください。現在のCSPは送信を禁止しているため、承認済み方式に必要な宛先のみ追加する別の開発作業が必要です。

## セキュリティ・配信上の制約

- 外部JS/CDN、解析、外部フォント、埋め込み、Cookie・ストレージ処理、秘密情報は追加していません。
- CSPで同一オリジンの静的ファイルのみ読み込み、通信API・フォーム送信・プラグインを制限しています。`unsafe-inline`や`unsafe-eval`は使用していません。
- HTMLのCSP metaでは`frame-ancestors`やHSTS等のHTTPヘッダーを設定できません。GitHub Pagesの配信挙動・HTTPSを公開後に確認してください。meta設定だけで完全な保護を保証するものではありません。
- リポジトリ内のdocsやtestsは公開方法によって配信されます。秘密・個人情報を記載しないでください。法的下書きを検索対象外にしても閲覧制限にはなりません。

## 公開作業手順（承認後のみ実行）

1. 最終承認の対象コミット・文面・公開範囲を記録する。
2. 公開用の文面とSEO設定をdevelopで確定し、同じブラウザーテストを再実行する。現行テストの制作版noindex確認は、承認された公開方針に合わせて更新する。
3. `git fetch origin`後、mainの更新・競合と既存GitHub Pagesの設定を確認する。既存の公開方法を尊重する。
4. 代表承認を記載したPR等でレビューし、承認対象のみmainへマージする。必要性と承認のないPages設定変更はしない。
5. 既存の公開処理の完了を確認する。正式URLでページ・画像・リンク・HTTPS・404・検索設定を確認する。
6. 不具合時は直前の公開コミットと差分を確認し、承認済みの復旧方針で変更をrevertする。履歴の強制書換えはしない。
